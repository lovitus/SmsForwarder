# 省电优化说明

## 1. 优化原则
本轮优化只处理“最小改动、最大收益”的路径：

- 不关闭保活。
- 不减少短信转发、Frpc、自动任务等核心功能。
- 不改变用户已有配置语义。
- 优先减少无意义的后台唤醒、数据库访问和持久化写入。

## 2. Cactus 计时器降频

### 原行为
启用 Cactus 后，`App.doWork()` 中存在一个每秒执行一次的计时器：

- 每秒从 IO 线程切到主线程。
- 每秒写入 `CactusSave.timer`。
- 每秒写入 `CactusSave.date`。
- 每秒更新 `mTimer`。

这个计时器只用于 Cactus 存活时长展示，不参与保活能力本身。

### 当前行为
- 计时器间隔从 1 秒改为 60 秒。
- 每次 `doWork()` 开始前会先 dispose 旧计时器，避免重复回调时留下多个计时器。
- Cactus 保活逻辑、无声音乐、一像素、前台服务配置均未关闭。

### 收益
- Cactus 开启时，计时器调度频率降低约 60 倍。
- SharedPreference 写入频率降低约 60 倍。
- 对保活功能无影响，只降低诊断计时精度。

## 3. 电量广播任务查询优化

### 原行为
每次收到 `ACTION_BATTERY_CHANGED` 都会先查询任务表：

- 查询是否存在电量条件任务。
- 查询是否存在充电状态条件任务。

即使电量、充电状态、插电状态都没有变化，也会执行这些数据库查询。

### 当前行为
- 仍然每次更新电池缓存：
  - `batteryInfo`
  - `batteryLevel`
  - `batteryPct`
  - `batteryStatus`
  - `batteryPlugged`
- 只有电量值发生变化时，才查询电量条件任务。
- 只有充电状态或插电状态发生变化时，才查询充电状态条件任务。
- 原本会触发的任务仍然触发。

### 收益
- 高频电池广播中的无效数据库访问减少。
- WorkManager 入队逻辑不变。
- 阈值触发和持续提醒语义不变。

## 4. 未改动项
以下能力本轮没有关闭或弱化：

- 前台服务。
- Cactus 开关。
- 无声音乐开关。
- 一像素开关。
- Frpc 自启动。
- 自动任务触发能力。
- 短信、通知、电话等广播处理。

## 5. 后续可选优化
如果后续继续做省电优化，仍建议遵循“不牺牲功能”的原则：

1. 优先清理只用于展示或日志的后台循环。
2. 对高频广播先判断状态是否真的变化，再查询数据库或入队任务。
3. 对 WorkManager 使用明确的唯一任务名，避免重复入队。
4. 不把保活能力整体关闭作为默认优化手段。
